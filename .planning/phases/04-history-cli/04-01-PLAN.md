**Architecture patterns** (from RESEARCH.md):
- Lexer/Parser separation (Lexer.hs handles whitespace/comments, Parser.hs handles grammar)
- Concrete parser type (`type Parser = Parsec Void Text`) for performance
- State Monad for temporal evolution (`State WorldState a`)
- Generic derivation for JSON instances

**Don't hand-roll**:
- Parser combinators (use Megaparsec `takeWhileP`, `symbol`, `lexeme`)
- State threading (use State Monad, not manual parameters)
- JSON encoding (use Generic derivation)

**Common pitfalls to avoid**:
- Polymorphic parser types (kills performance)
- Long alternative chains without factoring (backtracking death)
- Using `many satisfy` instead of `takeWhileP` (100x slower)
- Deep monad stacks (stick to single State or StateT IO)

**AST.hs** - Define simple Universal Law syntax:
```haskell
data Law = Law Text Expr deriving (Show, Generic)
data Expr = Var Text | Const Int | Add Expr Expr | If Condition Expr Expr
data Condition = Equals Expr Expr | GreaterThan Expr Expr
```
Add Generic instances for JSON serialization.

**Lexer.hs** - Follow RESEARCH.md example exactly:
- Define `type Parser = Parsec Void Text` (concrete type for performance, per Pitfall 2)
- Space consumer `sc` handles whitespace and `--` line comments, `{- -}` block comments
- Lexeme wrapper `lexeme = L.lexeme sc`
- Symbol parser `symbol = L.symbol sc`
- Identifier parser using `takeWhileP` (NOT `many satisfy`, per Pitfall 3)
- Reserved keywords helper

**Parser.hs** - Implement grammar:
- Top-level: `universalLaws = sc *> many law <* eof`
- Law syntax: `law <name>: <expression>`
- Expression: supports variables, constants, addition, if-then-else
- Use `lexeme` wrapper for all tokens
- Avoid deep backtracking - factor common prefixes per Pitfall 1

Example DSL:
```
law population_growth: population + 10
law tech_advance: if population > 100 then technology + 1 else technology
```

Use `errorBundlePretty` for user-facing parse errors (per Pitfall 6). Don't return raw error types.

Do NOT use polymorphic parser signatures. Do NOT use `many (satisfy pred)` for text. Do NOT create long `<|>` chains without factoring.
