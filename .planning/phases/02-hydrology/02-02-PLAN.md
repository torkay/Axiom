**D8 Flow Direction (from RESEARCH.md lines 343-359):**

```haskell
computeD8Flow :: ElevationGrid -> FlowGrid
```

Algorithm:
1. For each cell, examine all 8 neighbors (N, NE, E, SE, S, SW, W, NW)
2. Calculate elevation drop to each neighbor: currentElev - neighborElev
3. Find neighbor with maximum drop (steepest descent)
4. If max drop > epsilon (e.g., 0.01 for numerical tolerance), flow to that neighbor
5. If max drop <= epsilon (flat or uphill), mark as NoFlow
6. Return FlowGrid with direction for each cell

Use massiv's `makeArray Par` for parallel computation:
```haskell
computeD8Flow elevs = M.makeArray Par (size elevs) $ \ix ->
  let currentElev = elevs M.! ix
      neighbors = getNeighborsWithDir ix (size elevs)  -- [(FlowDirection, Ix2)]
      drops = [(dir, currentElev - (elevs M.! nix)) | (dir, nix) <- neighbors]
      (maxDir, maxDrop) = maximumBy (comparing snd) drops
  in if maxDrop > epsilon then maxDir else NoFlow
  where epsilon = 0.01  -- Based on typical DEM vertical accuracy
```

**Flow Accumulation (from RESEARCH.md lines 393-403):**

```haskell
flowAccumulation :: FlowGrid -> AccumulationGrid
```

Algorithm (topological sort approach, NOT recursion):
1. Build directed graph from FlowGrid (edges point downstream)
2. Topological sort of graph (provides ordering from outlets to sources)
3. Initialize accumulation: each cell starts with 1 (contributes itself)
4. Process cells in reverse topological order (sources first, outlets last)
5. For each cell, add its accumulation to downstream neighbor's accumulation
6. Return AccumulationGrid

**What to avoid:**
- Don't use recursion to accumulate (stack overflow on long river paths)
- Don't use simple iteration without topological ordering (incorrect accumulation)
- Don't forget epsilon tolerance for elevation comparisons (numerical precision pitfall from RESEARCH.md)
- Don't process flat areas incorrectly (NoFlow cells have no downstream neighbor)

**Helper functions:**
- `getNeighborsWithDir :: Ix2 -> Sz Ix2 -> [(FlowDirection, Ix2)]` - returns neighbors with their direction
- `directionToOffset :: FlowDirection -> (Int, Int)` - converts direction to grid offset (N = (-1, 0), etc.)
- `topologicalSortFlow :: FlowGrid -> [Ix2]` - topological sort of flow graph

Note: For topological sort, you can build a simple adjacency list and use standard topological sort algorithm, or convert to fgl graph and use fgl's `topsort`. Either is fine, but fgl approach is more robust.

**Build Drainage Graph (from RESEARCH.md lines 329-341):**

```haskell
buildDrainageGraph :: ElevationGrid -> FlowGrid -> AccumulationGrid -> DrainageNetwork
```

Algorithm:
1. Create node for each grid cell: `(nodeId, CellData cellPos elevation accumulation)`
2. Create edge from each cell to its downstream neighbor (from FlowGrid)
   - If FlowDirection = NoFlow, no outgoing edge (outlet or pit)
   - Otherwise, edge to neighbor in that direction: `(fromNodeId, toNodeId, FlowData 1.0)`
3. Use fgl's `mkGraph nodes edges` to build graph

Node numbering: Convert Ix2 to Int uniquely (e.g., `row * width + col`)

**Extract Rivers (threshold-based):**

```haskell
extractRivers :: AccumulationGrid -> DrainageNetwork -> Int -> [River]
```

Algorithm:
1. Filter cells where accumulation > threshold (e.g., 100 cells = significant river)
2. For each high-accumulation cell, trace upstream to sources:
   - Use fgl's `pre g node` to find upstream neighbors
   - Follow path until reaching cells with accumulation = 1 (sources)
   - Build River with path, length, sourcePos, mouthPos
3. Deduplicate rivers that share paths
4. Return list of River structures

**Find Outlets (for basin detection later):**

```haskell
findOutlets :: DrainageNetwork -> [Ix2]
```

Outlets are cells with no outgoing edges (outdeg = 0 in fgl).

**What to avoid:**
- Don't build drainage graph without elevation data - CellData needs elevation for visualization/analysis
- Don't use custom graph traversal - fgl provides `pre`, `post`, `dfs`, `bfs` (from RESEARCH.md "don't hand-roll")
- Don't set river threshold too low (< 10 cells) - produces noise, not meaningful rivers
- Don't set threshold too high (> 1000 cells) - may miss smaller streams in small grids

**Helper functions:**
- `cellToNode :: Sz Ix2 -> Ix2 -> Int` - convert grid position to unique node ID
- `nodeToCell :: Sz Ix2 -> Int -> Ix2` - inverse conversion
- `traceUpstream :: DrainageNetwork -> Ix2 -> [Ix2]` - follow path from cell to sources using fgl

Default river threshold: 100 cells (configurable parameter).
